# ADR-0004: 冷启动降级模型

状态：已采纳 ｜ 日期：2026-10-15（实施期收口）

## 背景

原设计「装包即对存量全量报错」会立即编译死（R3 落地压测 P0）。R4 又发现原「文件级
命中 ≤ 全局基线则降 Warning」的判据没有文件级数据支撑（全局 counts 算术上放行一切
新增文件）。

## 决策

1. `designguard init` 把存量命中写入基线，**含 per-file 快照**（`baseline.files`）。
2. 生成器判定：文件级未豁免命中数 ≤ 该文件 per-file 快照 → **降 Warning**；
   快照外文件（allowed = 0）或超快照命中 → **即时 Error**。判据有 per-file 数据支撑。
3. 硬零域命中永不降级（域内存量直接红）；豁免命中从不进入判定（先消费豁免）。
4. 配置缺失/非法 → 生成器自禁用 + MSBuild Warning（DGCFG001/002）；CLI verify 才
   exit 1。装包不炸编译。
5. CLI 的 `verify` 在基线段缺失时视为全 0 基线（严格）：「先 init 再 verify」是
   冷启动路径的一部分，文档明示。

## 后果

- 「即时反馈」与「存量共存」同时成立，且每一步都有数据依据。
- 实施期实证：MSBuild 以构建工作目录交付 item 相对路径——targets 投影必须
  `%(FullPath)`，否则快照键错位、降级失效（该 bug 已修复并进回归测试）。
