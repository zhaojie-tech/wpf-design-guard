# ADR-0007: CLI 门禁增加文件级棘轮（关闭「违规搬家」漏洞）

状态：已采纳 ｜ 日期：2026-10-17

## 背景

CLI `verify` 的棘轮只比对**全局计数**（每规则未豁免命中 ≤ baseline.counts）。
实测发现一个缺口：把违规从遗留文件 A 挪进新文件 B，全局总数不变，门禁仍绿。
生成器面不受影响（它按 per-file 快照判定：快照外文件 allowed=0，立即红），
但 CLI 面——CI 的最终门禁——看不见这次搬家。这与「新增违规必须令牌化或显式
豁免」的治理承诺不符。

## 决策

CLI 采用与生成器**同一套文件级判据**：

1. 对每个文件、每条规则，未豁免且非硬零域的命中数必须 ≤ 该文件在
   `baseline.files` 中的快照（文件不在快照中 = 0）。
2. 超出即 `PerFileRatchetViolation`，`verify` exit 2，`baseline --update` 拒绝
   红树（与全局超限同等对待）。
3. 硬零域命中不进入文件级计数（它们本身已是红）；已豁免命中不进入（豁免是
   独立轨道）；禁用规则的快照保留但不产生判定。
4. 全局棘轮保留：两层同时生效（文件级 ∧ 全局）。

## 后果

- 「违规搬家」在 CLI 与生成器两面同时红，两面口径一致（求值零漂移的延伸）。
- 新文件永远从 0 起算——这正是冷启动承诺的正面表述：存量共存，增量即时红。
- `baseline --update` 不能再把搬家后的状态一键吸收；必须先修复或显式豁免，
  再（如确需）重取基线。这提高了纪律成本，是有意的。
- 兼容性：已有基线的仓库若存在「历史搬家」状态，升级后 verify 会变红，按
  修复/豁免/重跑 init 三条路径处理；CHANGELOG 记录为行为变更。
