# ADR-0006: 滚动批次（其余 8 条）的版本口径与两处设计修订

状态：已采纳 ｜ 日期：2026-10-17

## 背景

设计文档的规则目录预留 17 条 ID，v0.1.0 交付 9 条，其余 8 条（DG0004/0006/0008/0009/
0011/0013/0014/0017）标注「v0.1.x 按 minor 滚动交付」。落地时出现三处需要定死的
口径冲突：

1. 版本号：版本化口径规定「新增规则 = minor」，而里程碑表又写「v0.1.x 滚动」——0.1.x 是补丁位，
   两条规则互相矛盾。
2. DG0006 的修复方向：修复方向约定写明「DG0006/0007 依 tokens 表的宽度/lineHeights 映射补值」，
   但 tokens 表只有 spacingLadder/fontSizes/lineHeights/hitTargetFloor，**没有宽度或
   圆角映射**——按字面实现会造出一个不存在的配置项。
3. DG0008 与 DG0017 的边界：两条都管命中区，容易重复报告。

## 决策

1. **版本口径以「新增规则 = minor」为准**：8 条规则合入 **0.2.0**（0.1.1 已用于采纳性
   升级，属文档/模板/外壳变更）。Tokens 运行库与令牌类型匹配规则顺延为后续 0.2.x，
   与 8 条规则解耦——规则机制先于令牌运行库交付的原始裁决不变。
2. **DG0006 只检测、不自动修复**（FixSupport.None）。设计假设的宽度/圆角映射在令牌表
   中不存在，凭空补一个映射会把「修什么」变成猜测；规则页明确写明「替换令牌是人工
   决策」。这是对修复方向约定的显式修订，不是遗漏。
3. **DG0008 只判实例显式值**（MinHeight/MinWidth/Height/Width 写在元素上），
   样式级地板由 DG0017 覆盖闸负责；两条规则在规则页互引，避免重复归因。
4. **DG0014/DG0017 是 CLI 全仓规则**：需要跨文件视图（MergedDictionaries 链、样式库
   定义处），生成器不得近似报告，否则两套计数漂移。RepoRuleEngine 与 XamlRuleEngine
   并列，共用同一套豁免/硬零/棘轮治理。

## 后果

- 17 条规则全部实装，引擎不再有「未实装」跳过面。
- DG0014 的多典同名隐式样式按声明顺序取「后者覆盖」，无法解析的 Source 计入未检面。
- DG0017 未配置 styleLibrary 或 glob 无匹配时计入未检面（不红、可见）。
- 版本线：0.2.0 = 8 条规则；Tokens 运行库随后按 0.2.x/0.3 交付。
